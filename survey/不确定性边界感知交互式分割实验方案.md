# 不确定性与边界感知的 FA 泄漏交互式分割实验方案

日期：2026-08-29

## 1. 方案定位

本方案针对葡萄膜炎荧光素眼底血管造影（FA）图像中的视网膜血管泄漏和黄斑水肿（ME）泄漏，设计一个“模型初分割—发现不确定区域—用户点击—局部边界修正”的交互闭环。

现有 UAG-SAM 实验已经完成并归档，后续不再把它作为主线。本方案保留 DINOv3 ConvNeXt-Tiny 粗分割模型作为可复用 baseline，但不再沿用 UAG 的多轮 soft-prompt 残差累加作为核心创新。新方法的重点改为：

1. 预测模型对哪些像素不确定；
2. 显式建模模糊的病灶边界；
3. 让系统推荐最有价值的下一次交互；
4. 只在局部高不确定区域进行高分辨率修正。

建议暂定方法名：

```text
FA-UBIR：Fluorescence-Aware Uncertainty-Boundary Interactive Refinement
中文：荧光先验引导的不确定性与边界感知交互式细化
```

这里的“interactive refinement”采用 SAM-style 的点提示思想，但如果没有使用 SAM/SAM2 的官方 image encoder、prompt encoder 和 mask decoder，论文中应称为“prompt-conditioned interactive refiner”，不能直接声称是 SAM 模型。

## 2. 研究假设和需要回答的问题

### 2.1 研究假设

FA 泄漏的主要困难不是普通区域内部分类，而是小病灶、低对比度、弥散边界和标注主观性。因而：

- uncertainty map 可以比随机点击更准确地找到需要医生确认的位置；
- boundary branch 和局部高分辨率 refinement 可以改善轮廓质量，而不必显著增加整图计算量；
- 交互收益应体现在“少量点击后的 Dice、Boundary F1 和面积误差”，而不仅是最终离线 Dice。

### 2.2 核心问题

实验需要回答以下问题：

1. 不确定性估计是否能找到真正的错误区域？
2. 边界感知模块是否能改善模糊边界和小泄漏灶？
3. 不确定性驱动的点击推荐是否优于随机点击和固定网格点击？
4. 真实误差或点击偏移存在时，模型是否仍然稳定？
5. 交互次数增加时，结果是否单调改善，是否可以自动停止？
6. 对最终临床关心的泄漏面积，改进是否仍然成立？

## 3. 数据、标签和数据卫生

### 3.1 数据划分

- 使用患者级五折交叉验证，严格保持现有 `f1`—`f5` 划分。
- 主实验使用 `mask_only_itksnap` 标注，不混用含 HRNet 结果的 `mask/` 目录。
- 验证集和测试集不得使用训练增强副本；清理并检查 `_aug` 样本，避免同一患者或同一原图泄漏到不同划分。
- 所有 DINO cache 必须按 fold 单独生成，训练和验证使用同一 checkpoint 口径。
- `dataset/` 仅作为只读输入，不移动、不重命名、不覆盖。

### 3.2 目标定义

沿用项目当前的多标签定义，以保证与现有 DINOv3 结果可比较：

```text
lesion_1 = (label == 1) OR (label == 3)
lesion_2 = (label == 2) OR (label == 3)
```

如果个别标签语义仍未完全确认，先报告二值总泄漏 `mask > 0`，同时保留两通道结果。所有实验必须明确是总泄漏、lesion_1、lesion_2 还是 macro Dice，不能混写。

### 3.3 分辨率和输入

- 保留全图 `768 x 768` 作为主分辨率，避免原论文 `512 x 512` 对小病灶和黄斑边界造成的损失。
- 局部细化使用以候选边界为中心的 `256 x 256` 或 `384 x 384` crop，并保留映射回原图的坐标。
- 推荐构造 FA-aware 三通道输入：
  - 原始灰度图；
  - CLAHE 或 gamma/contrast 增强图；
  - top-hat/high-pass 高荧光候选图。
- 先完成灰度单通道复制到三通道的 baseline，再单独加入 FA-aware 通道，避免预处理收益与交互收益混在一起。

## 4. FA-UBIR 模型设计

### 4.1 总体结构

```text
FA 图像
  │
  ├── DINOv3 ConvNeXt-Tiny encoder + FPN decoder
  │          └── 粗分割 logits p0（lesion_1 / lesion_2）
  │
  ├── Uncertainty head ───────────────┐
  ├── Boundary / distance head ──────┤
  └── 高荧光先验与边界冲突计算 ───────┘
                 ↓
           融合评分图 U
                 ↓
       推荐下一次前景/背景点击位置
                 ↓
  高分辨率局部 refiner（图像+mask+U+B+点击）
                 ↓
          局部 residual / 新 mask
                 ↓
        融合回全图并检查停止条件
```

### 4.2 粗分割器

使用现有 DINOv3 ConvNeXt-Tiny 多标签模型作为起点。第一轮实验冻结粗分割器，只训练新增加的 uncertainty head、boundary head 和局部 refiner，便于清楚测量新模块贡献。

粗分割器输出：

- 两通道 logits；
- 两通道概率 `p0 = sigmoid(logits)`；
- 可选多尺度 decoder feature，供辅助分支和局部 crop 使用。

后续如果局部 refiner 已验证有效，再进行一次全模型低学习率 fine-tune，作为独立实验，不与冻结版本混为一组。

### 4.3 不确定性估计

主方案采用“低成本熵 + 学习式误差预测 + 边界冲突”融合，不依赖 GT：

```text
u_entropy = 1 - 2 * |p0 - 0.5|
u_error   = learned uncertainty head(logits, decoder features)
u_conflict = |boundary_pred - gradient(p0)|
U = normalize(α * u_entropy + β * u_error + γ * u_conflict)
```

其中 `U` 为每个 lesion 通道的 uncertainty map。推荐初始权重 `α=0.5, β=0.3, γ=0.2`，只在验证集上调节，不在测试集上调参。

不确定性 head 的监督目标在训练阶段由 GT 构造，推理阶段不读取 GT：

```text
error_target = abs(p0.detach() - y)
boundary_band = dilate(y) - erode(y)
uncertainty_target = max(error_target, boundary_band)
```

为了避免不确定性 head 只学习“所有边界都不确定”，同时报告错误定位能力（error AUROC、AUPRC）和校准指标（ECE、Brier）。

可选的计算增强消融为 MC Dropout `K=4` 或多增强预测方差；它只作为不确定性估计对比，不作为默认主线，以控制交互延迟和显存。

### 4.4 边界感知分支

边界 head 对每个 lesion 预测以下一种表示，主实验只选一种：

- **boundary band**：由形态学梯度得到的 3～5 像素边界带；或
- **signed distance map**：边界内外带符号的距离变换。

建议先实现 boundary band，工程风险低；若边界 band 有稳定收益，再加入 signed distance 作为扩展消融。

边界损失可写为：

```text
L_boundary = BCE(boundary_pred, boundary_gt)
           + Dice(boundary_pred, boundary_gt)
```

主分割损失建议为：

```text
L_seg = Asymmetric/Focal Tversky + 0.5 * BCE
L_total = L_seg + λb * L_boundary + λu * L_uncertainty
```

初始设置 `λb=0.2`、`λu=0.2`，在小规模消融中扫描 `{0.1, 0.2, 0.4}`。

### 4.5 交互提示编码

用户可以提供：

- 前景点：表示这里应该是泄漏；
- 背景点：表示这里不应该是泄漏；
- 可选边界涂鸦，作为第二阶段扩展。

点击编码使用平滑 Gaussian heatmap，而不是固定二值 disk，并保留：

- 正负方向 `signed = positive - negative`；
- 点击距离图 `distance_to_click`；
- 点击可靠度 `reliability`。

训练中从 GT 自动模拟点击，但必须加入以下扰动：

- 点击位置 jitter：0、2、4 像素；
- 点击 dropout：0、0.1、0.2；
- 重复点击和边界附近点击；
- 正负点击数量不平衡。

这里的 GT 只用于离线模拟训练和评价，不得用于部署阶段的 click policy。

### 4.6 局部高分辨率 refiner

refiner 输入：

```text
局部 FA crop
+ 粗分割概率 p0
+ uncertainty U
+ boundary prediction B
+ positive/negative click heatmaps
+ 可选 distance-to-click
```

输出局部 mask residual 或局部 mask。只将 crop 内的修正融合回全图，crop 外保持粗分割结果，减少多轮交互导致的全局漂移。

推荐的第一版是轻量 U-Net/FPN，`base_channels=16` 或 `32`，AMP 开启，输入 crop 为 `256` 或 `384`。PointRend 风格的“只细化高不确定边界点”可作为第二阶段加分实验。

## 5. 交互策略和评价设置

### 5.1 点击位置策略

至少比较以下四种策略：

1. `Random`：在候选 ROI 内随机点击；
2. `Grid`：固定网格或最大距离采样；
3. `Oracle`：使用 GT 残差选择点击，只作为离线上限，不能作为部署结果；
4. `Uncertainty-Boundary Policy`：只使用当前预测、`U` 和 `B`，不读取 GT。

不确定性策略的候选得分可定义为：

```text
score = U * (1 + κ * boundary_conflict) * valid_roi
```

使用非极大值抑制或 farthest-point sampling 保证点击空间分散。推荐每轮只推荐 1 个点，评价 `0/1/3/5 clicks`。

### 5.2 点击极性

必须区分“点击位置推荐”和“点击标签”。

- **医生交互模式**：系统推荐位置，医生确认是前景还是背景；这是主要部署设定。
- **自动模拟模式**：实验脚本根据 GT 给点击赋予正确极性，用来测量位置策略本身的效果。
- **全自动模式**：根据当前 `p0` 推断正负，只作为附加 ablation，不能当作真实医生交互结果。

这样可以避免把 GT 提供的前景/背景标签误报为无 GT 的自动闭环。

### 5.3 停止规则

交互可以在满足任意条件时停止：

```text
max(U) < τu
或 mean(abs(mask_t - mask_{t-1})) < τΔ
或 已达到 5 次点击
```

验证集扫描 `τu`，测试集固定阈值。记录每张图实际点击数、停止原因和停止时 Dice。

## 6. 实验分阶段安排

### 阶段 0：数据与基线复核

目的：确保新方法没有数据泄漏或指标口径变化。

- 复核五折样本数量、患者级划分和 `_aug` 副本；
- 复核 `mask_only_itksnap` 解码和两通道标签转换；
- 复现当前 DINOv3 ConvNeXt-Tiny baseline 的 `click0`/全自动粗分割指标；
- 固定随机种子、阈值扫描、预处理和 cache 版本。

通过标准：五折粗分割结果与已有记录差异不超过约 0.5 个百分点；否则先处理复现差异。

### 阶段 1：边界和不确定性静态实验

不引入用户点击，只比较预测质量和不确定性定位能力：

| 编号 | 变体 | 目的 |
|---|---|---|
| S0 | 现有 DINOv3 粗分割 | 主 baseline |
| S1 | S0 + boundary head/loss | 测试边界监督 |
| S2 | S1 + learned uncertainty head | 测试错误区域预测 |
| S3 | S2 + FA-aware 三通道输入 | 测试荧光先验 |
| S4 | S2 + MC Dropout/增强方差 | 对比不确定性估计方式 |

阶段 1 先在 f1 上进行小规模扫描，再对最优 1～2 个配置做五折。每次只改变一个因素。

### 阶段 2：局部交互 refiner

固定阶段 1 最优粗模型，加入局部 refiner：

| 编号 | 点击来源 | crop | 目的 |
|---|---|---|---|
| I0 | 无点击 | 全图粗 mask | 交互前基线 |
| I1 | Random | 256 | 交互下限 |
| I2 | Oracle residual | 256 | 离线上限，不作部署结论 |
| I3 | Uncertainty-Boundary Policy | 256 | 主方法 |
| I4 | 主方法 + 384 crop | 384 | 检查上下文与细节取舍 |
| I5 | 主方法 + PointRend-style boundary points | 自适应 | 可选增强 |

报告 `0/1/3/5 clicks` 曲线，并单独报告与 Oracle 的差距。

### 阶段 3：交互噪声和稳健性

使用阶段 2 最优配置，固定五折模型，评价：

- jitter：0/2/4 像素；
- click dropout：0/0.1/0.2；
- 点击半径：4/8/12；
- 边界模糊程度和小目标面积分组；
- 55°/102° 视野分组（如果元数据可用）。

主要观察 exact-click 到 noisy-click 的性能下降，以及 lesion_2 的最差折表现。

### 阶段 4：五折正式实验和交互式演示

只对通过门槛的 1 个主配置和必要 baseline 做完整五折。输出：

- 每折 `best.pt`、`latest.pt`、`metrics.csv`、训练日志；
- click 0/1/3/5 的 mask 和 overlay；
- uncertainty、boundary、点击推荐可视化；
- 五折均值、标准差和 95% 置信区间；
- 一个可在本地运行的交互 demo，支持点击、撤销、重新计算和停止。

## 7. 消融矩阵和报告指标

### 7.1 最小论文消融矩阵

```text
A0  DINOv3 coarse baseline
A1  A0 + boundary supervision
A2  A1 + learned uncertainty
A3  A2 + uncertainty-boundary click policy
A4  A3 + local high-resolution refiner（完整方法）
A5  A4 + FA-aware input（若未在 A2 中加入）
```

交互策略单独做：

```text
P0  random clicks
P1  grid/farthest clicks
P2  oracle clicks（upper bound）
P3  uncertainty-boundary policy（deployment-safe）
```

### 7.2 必报指标

区域指标：

- lesion_1 Dice、lesion_2 Dice、macro Dice；
- IoU、precision、recall；
- 小病灶分组 Dice 和 lesion_2 recall。

边界指标：

- Boundary F1；
- Surface Dice；
- HD95、ASSD。

不确定性指标：

- error AUROC、error AUPRC；
- ECE、Brier score；
- uncertainty 与真实错误区域的 overlap。

交互指标：

- Dice@0/1/3/5 clicks；
- Boundary F1@0/1/3/5 clicks；
- 每次点击的 `ΔDice`、`ΔBoundary F1`；
- `NoC@90` 或达到固定 Dice 所需点击数；
- Oracle-policy gap；
- 平均停止点击数和停止率；
- 单图推理延迟和显存。

临床量化指标：

- 原始图像尺度的面积比例 MAE；
- 预测面积与标注面积的 Pearson/Spearman 相关；
- 面积分层后的误差分布；
- 如果已有临床字段，报告面积变化与 CMT/VC/BCVA 的相关性，但只使用训练折之外的预测结果。

```yaml
project:
```

该配置是实验起点，不代表已经验证的最优超参数。正式实验必须保存最终解析后的配置。

### 8.2 目录规范

所有新实验写入独立目录，不覆盖旧 UAG 结果：

```text
outputs/interactive_boundary_runs/fa_ubir_v1/
  f1/
    checkpoints/{best.pt,latest.pt}
```

数据集不复制到输出目录。DINO 特征只使用现有 compact cache 或按 fold 复用；不要为每个消融重新保存一份完整 cache。

### 8.3 存储和 watchdog 约束

当前剩余存储不足以容纳无上限的缓存，因此：

- 单个实验只保留 `best.pt` 和 `latest.pt`；
- 预测可视化限制为每折固定最多 40 张；
- TensorBoard 日志按实验保留，禁止重复写入原始图像；
- 临时 crop、AMP cache 和 dataloader 临时文件写入 `/tmp` 或受控目录，并设置上限；
- 每次训练前后记录 `df -h`，训练过程中监控输出目录增长；
- 可用空间低于 15% 时暂停并告警，低于 10% 时安全停止当前 epoch，不删除 checkpoint；
- 任何清理只针对明确的临时目录，不能删除数据、checkpoint、日志或已归档文件。

## 9. 成功判据和失败处理

### 9.1 进入毕设主结果的门槛

完整方法至少满足：

1. 五折 macro Dice 不低于现有 DINOv3 baseline，且不是单折偶然提升；
2. lesion_2 Dice 或 recall 不出现系统性下降；
3. Boundary F1 或 HD95 相对 baseline 有稳定改善；
4. `Dice@1/3 clicks` 优于 random policy；
5. noisy-click 相对 exact-click 的下降不超过 1.5 个百分点；
6. policy-click 与 oracle-click gap 被量化并且可解释；
7. 推理延迟和存储增量适合本地交互 demo。

### 9.2 失败时如何解释

如果 boundary head 提升了 Boundary F1 但 Dice 不升，应作为“轮廓质量改善”报告，而不是判定完全失败。

如果 uncertainty policy 不如 oracle，但明显优于 random，应把贡献表述为“部署安全的点击推荐基线”，不要夸大为自动纠错。

如果完整方法不稳定，保留阶段 1 的静态边界/不确定性结果，并将交互模块作为扩展实验；不要通过扩大点击次数或使用 GT 选择点击来掩盖问题。

## 10. 执行顺序

### 10.1 代码实现顺序

1. 新增 boundary target 和 boundary loss 单元测试；
2. 新增 uncertainty head、entropy/error target 和校准指标；
3. 新增 uncertainty-boundary click policy，确保推理函数完全不读取 GT；

```bash
# 3. f1 小规模消融
PYTHONPATH=src python scripts/train_interactive_boundary.py \
  --config configs/fa_ubir_ablation.yaml --fold f1

# 4. 通过门槛后再串行运行五折
PYTHONPATH=src python scripts/train_interactive_boundary.py \
  --config configs/fa_ubir_v1.yaml
```

上述文件名是规划中的新入口，代码实现前不能直接视为已经存在。每个阶段都先验证输出、显存和磁盘增长，再进入下一阶段。

## 11. 预期论文贡献

如果实验达到成功判据，论文可以形成以下叙事：

1. 针对 FA 泄漏边界模糊和小病灶不平衡问题，设计边界感知分割分支；
2. 通过熵、学习式错误预测和边界冲突构造无需 GT 的不确定性图；
3. 使用不确定性和边界联合策略推荐交互点，并以局部高分辨率 refiner 完成修正；
4. 在区域质量、边界质量、面积量化和交互效率四个层面进行五折验证。

该叙事的重点是“面向 FA 泄漏特性的可解释交互闭环”，而不是简单更换 backbone 或堆叠 SAM 模块。
